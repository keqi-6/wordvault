# 实现说明与偏差记录

本文件记录实际实现与《需求基线》之间的差异，以及造成差异的**已核实事实**。

## 1. 词向量：由 GloVe 6B 改为 glove-wiki-gigaword-50

- 需求基线写的是 GloVe 6B（862 MB）。
- 实测：downloads.cs.stanford.edu 在本机约 28 KB/s，862 MB 需要约 8.5 小时，不可行。
- 改用 HuggingFace 镜像上的 fse/glove-wiki-gigaword-50（gensim KeyedVectors 格式，20.5 MB + 76.3 MB），实测约 570 KB/s，92 秒下完。
- 影响：词向量维度从 300 降到 50。对「用 UMAP 把语义相近的词排到一起」这个用途，50 维足够；scenarios.py 里的大区质心也基于同一套向量，因此布局仍然自洽。
- 若以后要换成 300 维，只需替换 data/build/vec300.npy 的来源，重跑 parse_vectors.py 与 scenarios.py。

## 2. 真题语料：CET6-Resources 的真题是扫描图片

- 需求基线里首期 500 词定为「六级真题里出现频率最高的 500 个」。
- 实测：YinsinSirius/CET6-Resources 整库约 1.06 GB，但每套真题都是扫描图片（png/jpg），可直接解析的文本只有几个 root 级 md：
  - 历年翻译汇总.md（31 KB）
  - 可用词汇整理.md（1.4 KB，历年真题里出现过的词与短语）
  - 可用作文素材.md（2 KB）
  - 一些建议.md（2.7 KB）
- 用 git sparse-checkout 只取文本，实测只有 13 个文件、1.03 MB。
- 因此 parse_exam.py 的实际做法是：
  1. 从上述 md 里抽取文本，统计词频与可用的英文例句；
  2. 从 可用词汇整理.md 里抽出真正考过的六级词，作为真题词汇表，优先点亮；
  3. 不足部分按 ECDICT 的 frq（当代语料库词频序号）补足到 500。
- 第 3 步是替代方案，不是原始需求。要真正按真题词频排序，需要把 1 GB 扫描件下载下来做 OCR，那是另一项独立工作（首次下载约 4 小时）。
- parse_exam.py 保留了 PDF 与图片 OCR 通道：装了 pypdf / pytesseract + tesseract 后，重新运行即可自动使用。

## 3. Tatoeba 例句：本次未纳入

- 实测 downloads.tatoeba.org 约 13 KB/s，英文句 24.9 MB + 中文句 1.26 MB + 链接 150 MB，合计约 3.7 小时。
- 因此第一批不下载 Tatoeba；build_db.py 里的 Tatoeba 通道保留，文件存在时自动启用。
- 当前例句来源：真题 md 文本里的英文句子 + ECDICT 释义/搭配。

## 4. OMW 中文词网

- omw-1.4.zip（26.6 MB）已纳入下载清单，但 WordNet 的同义/反义关系不依赖它。
- 缺失时语义层依然可用，只是失去 synset 的中文词面映射。

## 5. 语法行为 / 语域与语用 / 概念与指代

- 三个维度没有任何开源数据源（已核实，见《需求基线》第 3 节）。
- 由 gen_dims.py 调用 DeepSeek 生成，只覆盖首期点亮的 500 词，结果在数据库里与其它字段区分存放；前端展示时标注「机器生成」。
- 没有模型 key 或调用失败时，字段留空，前端显示「待补充」，不伪造内容。

## 6. 实际落地的技术选择（与初版计划的差异）

| 项 | 计划 | 实际 | 原因 |
|---|---|---|---|
| ECDICT 来源 | 66 MB ecdict.csv | HuggingFace 镜像上的离线 SQLite 包（49 MB，80 秒下完，770,611 条） | 原始 CSV 在本机实测只有 20-40 KB/s，要 30 分钟以上 |
| 词向量降维 | UMAP | numpy SVD 取前 3 主成分 | umap/sklearn 装不上（pip 走境外源反复 SSL 失败）。实测 38 个语义簇词，PCA 三维的邻域完全够用：airport -> terminal/passenger/runway/airline/flight；doctor -> nurse/medicine/surgery/clinic/patient；however -> although/consequently/therefore/nevertheless |
| WordNet 读取 | nltk | 直接解析 data.noun / data.verb / data.adj / data.adv | 去掉 nltk 依赖；解析 117,374 个 synset 只需 0.6 秒 |
| 形态层 | MorphoLex | MorphoLex（xlsx 30 张表）+ WordNet 的派生关系（'+' 指针）双来源 | MorphoLex 覆盖 21,967 词（首期 500 词全覆盖），WordNet 派生关系补上合成词与派生对 |
| 后端 sqlite | better-sqlite3 | Node 内置 node:sqlite | better-sqlite3 在 Node 24 上没有预编译包，node-gyp 源码编译失败；node:sqlite 零原生依赖，API 基本一致 |
| 时间戳 | ISO 本地时间 | 统一 UTC 的 YYYY-MM-DDTHH:MM:SSZ | 原先 Python 写 +08:00、Node 写 .000Z，字符串比较错位，导致「到期 500 个」查出来是 0 |
| 卫星星 | 每词最多 5 个 | 每词最多 3 个，且只挂在六级词上 | 45,026 词的星空被稀释；收紧后 26,608 词 |

## 7. 端到端实测结果（真实数据库 + 真实浏览器，非模拟）

- 数据库：26,608 词 / 121,612 条边 / 42,906 义项 / 52,323 搭配 / 36,816 中文词面 / 2,453 微题
- 后端接口逐个实测通过（health / sky / scenarios / word / search / graph / assessment / review / stats / export）
- 复习闭环实测：队列到期 500 → 取 3 个词 → 每题 3 问（词义、拼写、搭配）→ 答对升 L1（strength 0.2083，次日到期）→ 答错降 L0（strength 0.05，错误类型 spelling）→ 统计与 CSV 同步
- 星空渲染：headless Edge + swiftshader，26,608 颗星、10 个情景大区，25 fps，零控制台报错；截图 docs/verify/sky-real-2.png

## 9. 主观维度已生成（本轮完成）

- scripts/pipeline/gen_dims.py 用本机 DeepSeek key 跑完 34 个批次，**首期 500 词 100% 覆盖** syntax / register / concept 三个字段。
- 抽样（absolutely）：
  - syntax：副词，修饰形容词、动词或整句；可单独作答。
  - register：通用；口语中表强烈同意，正式语境表完全地。
  - concept：表示「绝对地、完全地」；口语可表「当然、确实」。
- 这些内容在数据库里与有数据支撑的字段分开存放，前端展示时标注「机器生成」。

## 10. 微题干扰项质量（本轮改进）

- 初版按同情景随机挑干扰项，出现「学术的」对「性别」这类一眼可排除的选项。
- 改为：**同词性优先 → 释义长度接近 → 同情景**，三级回退。
- 改进后（absolutely）：答案「当然」，干扰「奸诈 / 无礼 / 无疑」，长度与词性都接近。
- 仍未做：用词向量挑「语义相近但不对」的干扰项，那是下一步的优化。
